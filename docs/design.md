# 설계와 안전 규칙

## 설계에서 신경 쓴 점

- **장비가 말한 것만 믿습니다.** 버튼을 눌렀다고 `급수 중`이 되지 않습니다. 화면 상태는 장비의 응답으로만 바뀌고, 응답이 없으면 실패로 기록한 뒤 중지 명령을 보냅니다.
- **자동화의 경계를 코드로 정했습니다.** 자동 제어는 환기와 조명만 움직입니다. 펌프를 켤 경로가 없으므로, 규칙을 잘못 정해도 사람의 확인 없이 물이 나오지 않습니다.
- **동시성은 DB가 보장합니다.** 상태 변경은 조건부 UPDATE 하나로 처리하고, 구역당 진행 중인 급수 하나는 부분 유니크 인덱스로 막습니다. 여러 사람이 동시에 눌러도 펌프 명령은 한 번만 나갑니다.
- **재시작해도 잃지 않습니다.** 알람과 응답 기한을 메모리가 아니라 저장된 시각으로 계산해, 서버가 재시작되어도 이어서 처리합니다.
- **권한은 서버에서 다시 확인합니다.** 버튼을 숨기는 것과 별개로 제어할 때마다 세션과 역할을 다시 읽으므로, 역할 변경과 로그아웃이 열린 화면에도 바로 적용됩니다.
- **공격 표면을 줄였습니다.** 웹, 백엔드, 브로커는 이 컴퓨터에서만 수신하고 네트워크에는 HTTPS 프록시 하나만 엽니다. WebSocket은 CORS로 보호되지 않아 Origin을 직접 검사하고, 푸시 구독 주소는 내부망 요청에 악용되지 않도록 공식 서비스만 허용합니다.
- **기록이 제어를 막지 않습니다.** 제어 이력과 센서 기록은 실패해도 오류만 남기며, 급수 중지 같은 동작을 지연시키지 않습니다. 비밀번호는 기록에 남기지 않습니다.
- **접근성:** 상태를 색만으로 구분하지 않고, 차트에 같은 데이터의 표를 함께 둡니다. 드래그 선택은 터치와 키보드용 체크박스로도 할 수 있고, 움직임 줄이기 설정을 따릅니다.
- **검증:** 실제 MQTT와 소켓을 쓰는 통합 테스트, 실제 브라우저 테스트, 네트워크 모드 테스트, 과거 DB 버전의 업그레이드 테스트, 메모리 측정을 저장소에 함께 둡니다.

## 안전 규칙

코드를 바꿀 때 지켜야 하는 규칙입니다.

- 사람의 확인이나 요청 없이는 물을 주지 않습니다. 자동 제어는 환기와 조명만 움직이며 펌프에 명령할 방법이 없습니다.
- 카드 상태와 색상은 클릭이 아니라 장비 응답에 따라 바뀝니다.
- 펌프는 장비 쪽에서 최대 300초 후 스스로 멈춥니다.
- 구역마다 진행 중인 급수는 하나뿐이며, DB의 부분 유니크 인덱스가 보장합니다. 여러 사람이 동시에 확인해도 펌프 명령은 한 번만 나갑니다.
- 같은 `commandId`를 다시 보내도 명령은 다시 실행되지 않습니다.
- 토양 수분이 70% 이상이거나 장비가 오프라인이면 펌프 명령을 보내지 않습니다.
- 장비 응답이 없으면 `실패`로 기록하고 중지 명령을 보냅니다.
- 펌프는 알람 확인이나 물 주기 요청으로만 시작합니다. 직접 켜는 수동 스위치는 환기와 조명뿐입니다.
- 웹, 백엔드, 브로커는 `127.0.0.1`에서만 수신합니다. 브로커에는 인증이 없으므로 네트워크에 열면 안 됩니다. 네트워크 접속은 `apps/lan`의 프록시를 거칩니다.
- 첫 관리자 생성(`/api/setup`)은 허용된 Origin이 있는 요청만 받고, 프록시를 통하면 이 컴퓨터에서만 가능합니다.
- 제어 이력 기록에 실패해도 장비 제어는 막히지 않습니다.
- 푸시 구독 주소는 주요 브라우저의 공식 푸시 서비스만 허용합니다. 서버가 그 주소로 요청을 보내므로, 임의 주소를 받으면 내부망 공격에 쓰일 수 있습니다.
- Socket.IO는 허용된 Origin과 유효한 세션만 받고, 제어할 때마다 세션과 역할을 다시 확인합니다.

## 알려진 한계

- 서버가 꺼져 있으면 정해진 시각의 알람과 자동 제어가 멈춥니다.
- 같은 Wi-Fi 안에서 쓰는 구성이며 인터넷 공개용이 아닙니다.
- 실제 장비 없이 시뮬레이터로 동작합니다. 실제 장비를 연결하려면 브로커 인증과 TLS, 설비 용량에 맞춘 순차 급수가 필요합니다.
- 네트워크 모드는 이 컴퓨터의 실제 IP와 모바일 에뮬레이션으로 시험했으며, 실제 휴대폰과 태블릿에서는 아직 시험하지 않았습니다.
- 자체 서명 인증서에서 WebSocket을 거부하는 기기는 HTTP 폴링으로 동작합니다.
- 네트워크 모드의 자체 서명 인증서에서는 웹 푸시가 켜지지 않을 수 있습니다. 신뢰된 인증서를 쓰는 방법은 [네트워크 모드](network.md)를 봅니다. 실제 푸시 서비스를 거쳐 기기까지 전달되는 과정은 아직 시험하지 않았습니다.
